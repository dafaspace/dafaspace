# dafaspace.com

Project specifics that win over the portfolio rules in `My Apps/CLAUDE.md` where they differ.

Personal site of Daniel Fainberg: who he is, and a card for each dafaspace project. One
`index.html`, no build step, on GitHub Pages behind Cloudflare (SSL mode "Full", see
`_HQ/DOMAINS.md`). A push to `main` is a release; Pages deploys in about a minute.

## Where the facts come from

`_HQ/PROJECTS-2026-11.md` holds every project's stage, name, links and languages. Ask the _HQ
session about any project before changing its card. A card says only what is true today: no
"coming soon", no feature the build does not have.

## Languages (Dafa, 2 Nov 2026)

- The site carries **every language used by any dafaspace app**, the union, not a house subset.
  On 2 Nov that is 12: en ru uk ka es fr de it pt-BR tr ja he. Hebrew is right-to-left, so the
  layout handles `dir="rtl"`.
- **When any app adds a language, the site adds it too.**
- Translation starts once the English text has settled. Before the first translation ships:
  all texts in one keyed file, each translation storing a hash of the English it came from; a
  nightly check that flags stale translations on the Sites line, and that also compares the
  union of the apps' language lists (the places in the language table of
  `_HQ/PROJECTS-2026-11.md`) with the site's languages; status badges as a small fixed set of
  phrases.
- Every English edit updates all languages in the same commit. The nightly check is a safety net,
  not the plan.
- Review: Dafa reads ru and uk; a native reader checks ka; the rest get a back-translation check.
  App names are never translated.
- URLs and switcher (Dafa, 2 Nov): both.
  - Each language has its own static page at `/xx/` (`/ru/`, `/ka/`, ...), with `hreflang` links
    and `x-default` pointing to `/`.
  - The switcher is Underpicture's language pill (Dafa, 3 Nov: made for a site, unlike
    Cinemail's settings row). Choosing a language opens the same page in that language and
    remembers the choice.
  - `/` is always English. When the browser language is one of ours, a quiet one-tap offer
    appears ("Open in Russian?"). There is no automatic redirect, per the way-back rule.
  - The pages are generated by a small script from one keyed text file, and the output is
    committed. This is a deliberate exception to "no build step": one file is edited by hand, not
    twelve.

### How it works (built 3 Nov 2026, English only so far)

- `index.html` stays the one page edited by hand, in English. Each translatable text carries a
  key: `data-t="key"` for an element's inner HTML, `data-t-attr="alt:key,title:key"` for
  attributes. A new text without a key stays English on every page, so **give every new text a
  key**. The same key used twice must have the same English (statuses, badges).
- `i18n/languages.json` is the list of the site's languages, with each one's own name and
  direction. `i18n/en.json` is generated: every key, its English, and a hash.
- A translation is `i18n/<code>.json`, shaped `{ "key": { "text": "...", "from": "<hash from en.json>" } }`.
  `offer.text` names the reader's own language ("Open this page in Russian?", written in Russian).
  App names stay untranslated.
- `node tools/i18n.mjs build` regenerates `en.json`, the `I18N` block in `index.html` (canonical,
  hreflang, `SITE_LANGS`), and `<code>/index.html` for every language with a translation file.
  **Run it after every edit of `index.html`** and commit its output with the edit.
- `node tools/i18n.mjs check` reports, in one line:
  - texts whose English changed since translation (stale) and keys with no translation (missing);
  - generated pages older than `index.html`, which also happens after the weekly FRESH script;
  - a language an app has that the site lacks;
  - an app whose language list cannot be read;
  - languages not translated yet.
  It exits 1 when there is anything. `checkSiteLanguages()` in the same file returns `{ ok, line }`
  for the nightly `_portfolio/check-sites.mjs`.
- **Translations are automatic in one sense: nobody has to remember them** (Dafa, 3 Nov: no API).
  - The session that edits English translates the changed keys into every language, in the same
    commit, by itself.
  - `tools/hooks/pre-commit` (installed with `git config core.hooksPath tools/hooks`, already set
    in this checkout) runs `node tools/i18n.mjs gate` on the staged files. The commit stops when a
    translation is stale or missing, or a page is behind `index.html`. It prints what to do.
  - Languages not translated yet never block, and neither do the apps' language lists.
  - Never commit with `--no-verify` to get past it.
- The switcher is Underpicture's language pill (a native select), hidden while English is the only
  language. `/` offers the reader's language once, in that language, and never redirects.

## Look

- The accent is `#D96512`. App names on cards all use `var(--text)`.
- Status and "Updated this week" badges use the muted style.
- `h1` is 24px everywhere.
- The bio folds under "More about me" so the first project card fits on a phone screen. Keep it
  that way.
- Fonts: DM Sans for Latin from Google Fonts; the script partners are self-hosted in `fonts/`
  (Tastebook, Dafa 3 Nov 2026, the same in Cinemail and Tunemail): Geist for Cyrillic, Noto Sans
  Georgian, IBM Plex Sans Hebrew, Noto Sans JP. Each `@font-face` keeps its unicode-range, so the
  English page downloads none of them. Noto Sans JP lives in `fonts/ja.css`, loaded only for the
  Japanese page or a Japanese browser. `h2` in ka, he and ja is 700; Georgian also `font-stretch: 62.5%`.
